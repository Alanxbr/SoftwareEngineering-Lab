## 一、教材第一章学习笔记

### 1. 软件危机（Software Crisis）
软件危机是指在计算机软件开发和维护过程中遇到的一系列严重问题：
- 成本超出预算
- 进度超出计划
- 软件质量差
- 软件不符合需求
- 软件难以维护

### 2. 软件工程定义
- **Bauer定义**：建立并使用完善的工程化原则，以较经济地获得能在实际机器上有效运行的可靠软件的一系列方法
- **IEEE定义**：将系统化的、规范化的、可度量的方法应用于软件的开发、运行和维护

### 3. 软件工程三要素
- **方法**：完成软件工程的技术手段（结构化方法、面向对象方法）
- **工具**：为过程和方法提供自动化支持（IDE、Git、建模工具等）
- **过程**：贯穿开发各环节，建立里程碑

### 4. 软件生存周期
1. 计算机系统工程 → 2. 需求分析 → 3. 设计 → 4. 编码 → 5. 测试 → 6. 运行维护

### 5. 软件过程模型
- 瀑布模型（线性、文档驱动）
- 增量模型（分批交付）
- 螺旋模型（风险驱动）
- 原型模型（快速原型）
- 敏捷开发（迭代、快速响应变化）

## 二、课程设计选题

### 推荐选题：在线图书管理系统

**选题理由**：
1. 符合软件工程全流程实践（需求→设计→编码→测试→维护）
2. 涉及多角色（学生、管理员），便于需求分析
3. 功能模块清晰（借阅、归还、续借、图书管理）
4. 难度适中，适合课程设计周期

**核心功能模块**：
| 模块 | 功能描述 |
|------|----------|
| 用户管理 | 注册、登录、权限控制 |
| 图书管理 | 图书信息CRUD、分类管理 |
| 借阅管理 | 借书、还书、续借、逾期处理 |
| 查询统计 | 图书检索、借阅记录查询 |
