#### 3.5 阅读教材第一章

阅读《软件工程-实践者的研究方法》第一章，主要内容包括：

1. **软件危机**：软件开发和维护过程中遇到的一系列严重问题，包括成本超支、进度延误、质量差、难维护等
2. **软件工程定义**：将系统化的、规范化的、可度量的方法应用于软件的开发、运行和维护
3. **软件工程三要素**：方法、工具、过程
4. **软件生存周期**：需求分析→设计→编码→测试→运行维护
5. **软件过程模型**：瀑布模型、增量模型、螺旋模型、原型模型、敏捷开发
6. **软件工程七条原则**：阶段评审、严格产品控制、现代编程技术等

#### 3.6 确定课程设计选题

经过调研和分析，选择 **"隐私计算数据共享平台"** 作为课程设计题目：

### 五、实验总结与心得

#### 5.1 实验收获

1. **工具配置能力提升**：掌握了Git、Python、Node.js等开发工具的安装与配置方法，理解了环境变量配置的重要性。

2. **版本控制概念建立**：通过Git和GitHub的实践，理解了版本控制的核心概念，包括仓库、提交、分支、远程仓库等，认识到版本控制在团队协作中的重要性。

3. **软件工程认知深化**：通过阅读教材第一章，了解了软件危机的历史背景和软件工程的诞生原因，理解了软件工程方法论的重要性。

4. **项目规划能力**：通过选题和实验计划的制定，初步掌握了如何分析需求、制定开发计划的方法。

#### 5.2 遇到的问题与解决

| 问题 | 解决方法 |
|------|----------|
| Git push需要认证 | 使用Personal Access Token进行认证 |
| Java编译命令找不到 | 使用完整路径或配置环境变量 |
| 选题过于常见 | 结合专业方向选择冷门但有技术含量的题目 |

#### 5.3 对软件工程的理解

软件工程不仅仅是编写代码，更重要的是采用系统化、规范化的方法来管理软件开发过程。通过本次实验，我认识到：

1. **工具链的重要性**：合理的工具链能大大提高开发效率
2. **版本控制的必要性**：Git等工具能有效管理代码变更，支持团队协作
3. **文档的价值**：实验计划、需求文档等是软件工程不可或缺的组成部分
4. **流程规范的意义**：遵循软件工程流程能减少开发风险，提高软件质量
